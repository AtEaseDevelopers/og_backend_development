## How the user works

- The user sends requirements **one item at a time**, often with screenshots, in casual Malaysian English ("jiu" = then).
  Only work on items the user sends.
- **Never commit or push unless the user asks.**
- Positive/confirm buttons go on the **right**.
- Keep light/dark mode and phone width working.
- Usage-conscious: do small changes directly; avoid big multi-agent workflows (at most one builder + one reviewer).
- The live server is `ogtransport.at-eases.com`. The user runs server commands themselves
  (after a deploy: `composer install --no-dev --optimize-autoloader`, `php artisan migrate`, `php artisan optimize:clear`).

## Environment notes (Windows, Laragon)

- Run PHP only via: `C:/laragon/bin/php/php-8.3.3-Win32-vs16-x64/php.exe -d display_startup_errors=0`
  (lint with `-l`, then `artisan view:clear` and `artisan optimize:clear`; `artisan test` has 1 expected failure in `tests/Feature/ExampleTest.php`).
- Local site: `http://og_backend_development.test/admin` (tenant `KL`). Local seed login: see the database seeders.
  The local site is plain HTTP, so the live camera (QR scanning) only works on the HTTPS server.
- Files use CRLF: `sed` with `$` anchors fails; use the Edit tool or a small Python script.
- **Never put a Blade component tag (`<x-...>`) inside a CSS or HTML comment** in a `.blade.php` file (it broke every page once).
- Livewire testing in the browser: `Livewire.all().find(c => c.name.includes('...'))`. Globals `window.OgDateRange` and `window.OgSearchableSelect` exist.
- Test data changes inside a rolled-back DB transaction; only create real local records when the user asks.

## Business rules the user confirmed (carried over; a new requirement may change them)

- **Pricing precedence:** customer special price, then UOM price list, then manual price. Never drop a product line just because it has no price.
- **Table filters (changed 10 Oct 2026):** tables get **Excel-style column filters** (funnel in each header: sort A-Z / Z-A, a checklist per field the column shows, search, select all). Done on Orders first; the filter card stays.
- **Store** (Consignor Pickup/Store toggle) = an O&G branch, with its address pre-filled.
- **PIC name + contact number** on both consignor and consignee. **Blank consignor stays blank.**
- **Payment term by customer type:** Credit customer: Credit / Cash / COD; COD customer: COD only; Cash customer: Cash only.
- **COD:** CSN on confirmation, no invoice; COD invoice issued once fully paid and every driver collection is verified.
  **Term:** CSN on confirmation, invoice generated by Admin when ready; no Add payment on the order page.
